# Research Assessment Wiki

Open, expert-curated criteria for evaluating researchers in each of the ~4,500
[OpenAlex topics](https://docs.openalex.org/api-entities/topics): key journals and
conferences, awards, other contributions, and suggested weights.

> **Status: pilot.** Pages generated by scripts or a language model are drafts and
> have **not** been reviewed by domain experts yet. Each page shows its review status.

## How it works

```
OpenAlex API ──► scripts/ ──► wikitext ──► MediaWiki (via bot account)
                                              ▲
                     domain experts review and propose changes
```

- **Hierarchy**: 4 domains → 26 fields → ~250 subfields → ~4,500 topics, taken from OpenAlex.
- **Inheritance**: most criteria (awards, weights) are defined at subfield level;
  topic pages only store what differs, plus their own venue list.
- **Structured data**: every page is built from templates whose fields are stored in
  Cargo tables, so the criteria can later be queried and used to compute metrics.

## Repository layout

| Path | Contents |
|---|---|
| `docker/` | Dockerfile and Compose file for the wiki server (MediaWiki 1.43 + Cargo, Page Forms, Approved Revs) |
| `scripts/` | Data pipeline: fetch from OpenAlex, generate wikitext, upload |
| `data/` | Cleaned snapshots of the source data (raw downloads are not committed) |
| `wiki/` | Templates, forms and Lua modules, as they are stored on the wiki |

## Uploading content

The scripts run on your own computer and edit the wiki through its API with a bot account.

1. On the wiki, create a bot password at `Special:BotPasswords` with the grants
   *High-volume editing*, *Edit existing pages* and *Create, edit, and move pages*.
2. Copy `.env.example` to `.env` and fill in `WIKI_BOT_USER` and `WIKI_BOT_PASSWORD`.
   `.env` is ignored by git.
3. Open the encrypted tunnel in a separate terminal and keep it running:

   ```bash
   scripts/upload_channel.sh
   ```

4. Refresh the OpenAlex snapshot (optional, it is committed in `data/`):

   ```bash
   python3 scripts/fetch_openalex_hierarchy.py
   ```

5. Upload. Start with a pilot (templates, all domains/fields/subfields, and the
   topics of one subfield), then everything:

   ```bash
   python3 scripts/upload_hierarchy.py --subfield 1705
   ```

   ```bash
   python3 scripts/upload_hierarchy.py
   ```

   `--dry-run DIR` writes the generated wikitext to files instead of uploading.
   Re-running is safe: unchanged pages are skipped, and on entity pages only the
   block between `BOT:BEGIN openalex` and `BOT:END openalex` is replaced.

6. After the first upload, and whenever a template's table definition changes,
   build the Cargo tables on the server (in `~/wiki`). New tables must be created
   first; the second command then fills all tables from the pages:

   ```bash
   docker compose exec mediawiki php maintenance/run.php ./extensions/Cargo/maintenance/cargoRecreateData.php --create-missing-tables-only
   ```

   ```bash
   docker compose exec mediawiki php maintenance/run.php ./extensions/Cargo/maintenance/cargoRecreateData.php
   ```

   Pages saved after a table exists are stored automatically; no rebuild is needed
   for ordinary uploads. After a rebuild, run the upload once more (or purge the
   domain, field and subfield pages) so their lists are re-rendered.

The pages show shares (percent of the parent, per mille of all works) rather than
absolute counts, which change daily. Raw counts are stored in the Cargo tables only.
